# VK AI Challenge — предсказание валидности жалоб (`is_valid`)

Бинарная классификация на табличных данных, метрика — **F1 положительного класса**.
Итоговое решение: ансамбль из 4 градиентных бустингов (2 × CatBoost, 2 × LightGBM),
усреднённых по 3 seed'ам, с **rate-правилом отсечения** вместо порога вероятности.

| | |
|---|---|
| Точка отсчёта организаторов (все единицы) | F1 = `0.2347083926` |
| Предыдущий подтверждённый public F1 (frozen champion) | **`0.4792176039`** |
| Итоговый файл для платформы | `submission.csv` (= `submissions/submission_equal4_m180.csv`) |
| Код обучения и инференса | `solution.py`, `solution.ipynb` |
| Схема валидации | 4 хронологических блока по 7 446 строк (размер hidden test) |

## 1. Что здесь нового по сравнению с предыдущим решением

Предыдущее решение (frozen champion, F1 `0.4792176039`) — recency-CatBoost + два LightGBM
с весами `0.70/0.20/0.10` и фиксированным порогом `0.504`. До него было отклонено 23
семейства гипотез (`docs/Проверенные гипотезы и причины их отклонения.md`) — практически
все идеи по фичам и моделям. Поэтому здесь атакована не модель, а **операционная точка**.

**Ключевое наблюдение.** Организаторы публикуют скор submission из всех единиц:
`sample_f1 = 0.2347083926`. Для предсказания «все единицы» `F1 = 2p / (1 + p)`, значит
доля позитивов в hidden test известна точно:

```
p = 0.2347083926 / (2 - 0.2347083926) = 0.13295729  ->  0.13295729 * 7446 = 990 позитивов
```

Champion помечал единицами 1 426 строк, то есть `m = 1426 / 990 = 1.44` от числа истинных
позитивов. На честной временной кросс-валидации оптимум лежит существенно выше — около
`m = 1.8` (`artifacts/analysis_rate_curve.csv`, скрипт `src/rate_curve.py`):

| вариант бленда | m=1.4 | m=1.5 | m=1.6 | m=1.7 | **m=1.8** | m=1.9 | m=2.0 | m=2.2 |
|---|---|---|---|---|---|---|---|---|
| champion `0.70/0.20/0.10` | 0.4110 | 0.4148 | 0.4166 | 0.4187 | **0.4191** | 0.4190 | 0.4176 | 0.4132 |
| равные веса, 4 компоненты | 0.4164 | 0.4177 | 0.4183 | 0.4190 | **0.4223** | 0.4230 | 0.4212 | 0.4147 |

(среднее F1 по 4 фолдам; максимум по строке — плато `m = 1.7…2.0`)

Почему это не «подгонка порога», которая ранее уже отклонялась:

1. Правило задаётся не порогом вероятности, а **числом единиц** — оно инвариантно к любой
   монотонной раскалибровке между train и test, поэтому переносится через сдвиг
   распределения, на котором ломались пороговые правила.
2. Число позитивов в test не оценивается моделью, а **известно** из скора организаторов.
3. Множитель `m` выбран по 4 хронологическим фолдам, а не по одному последнему, и лежит
   на плоском плато, а не в остром максимуме.

Ожидаемый эффект: для champion-бленда переход `m = 1.44 -> 1.8` добавляет `+0.008` F1 на
CV. Правило безубыточности — расширять `k`, пока предельная точность добавляемых строк
выше `F1 / 2`; предельная точность в полосах `1.44…1.8` на CV равна `0.21…0.26`
(`artifacts/analysis_rate_bands.csv`) при `F1 / 2 ≈ 0.21`, а на тесте ранжирование заметно
точнее (precision champion'а на тесте `0.406` против `0.34…0.37` на CV), поэтому запас
сохраняется. Это единственный компонент решения, который **нельзя** проверить офлайн до
конца: обе стороны неравенства зависят от того, насколько тест «легче» валидации.

Второе, меньшее улучшение: **усреднение по 3 seed'ам и добавление neutral CatBoost в
бленд с равными весами** поднимает PR AUC с `0.4096` до `0.4121` и F1 на плато на `+0.003`
(`artifacts/analysis_ranking.csv`). Веса намеренно равные: любой подбор весов на фолдах
раньше не переносился между фолдами (семейство гипотез 4 в каталоге).

## 2. Данные и признаки

`DATA_DESCRIPTION.md` — описание 38 колонок. Признаки (полный код — `solution.py`):

* временные: компоненты `first_event_time`, возраст контента, возраст аккаунтов,
  разницы регистраций, календарные признаки;
* профильные: пол/возраст/страны отправителя и объекта жалобы, совпадения стран,
  бакетизация возрастов;
* bot-скоры: разности, суммы, отношения;
* тип жалобы × причина, взаимодействия с платформой/ОС;
* агрегированные счётчики активности в логарифмической шкале;
* частотные кодировки и групповые статистики, посчитанные на `train + test` **без
  целевой переменной** (транздуктивно, утечки метки нет);
* out-of-fold target encoding для `claim_type`, `claim_reason_start`, страны, платформы и
  для сущностных ключей `id_content_owner`, `id_content`, `owner × claim_type`,
  `owner × claim_reason_start` (K-fold OOF на train, применение к валидации/тесту по
  маппингу, посчитанному только на train-префиксе);
* флаги «сущность встречалась в прошлом» и время от начала выборки.

## 3. Модели

| компонента | модель | ключевые параметры | вес в бленде |
|---|---|---|---|
| `cat_all` | CatBoost | depth 7, l2 3, lr 0.03, balanced weights | 0.25 |
| `cat_recent` | CatBoost | depth 7, l2 9, lr 0.03, экспоненциальный вес по времени, half-life 105 дней | 0.25 |
| `lgb_neutral` | LightGBM | leaves 48, min_child 35, l2 2, lr 0.03, `scale_pos_weight` 1 | 0.25 |
| `lgb_diverse` | LightGBM | leaves 64, min_child 25, l2 3, lr 0.025, `scale_pos_weight` 2 | 0.25 |

Каждая компонента обучается на 3 seed'ах (`42, 2026, 777`), вероятности усредняются.
Число итераций выбирается на **внутреннем** хронологическом holdout'е (последние 7 446
строк обучающего префикса), после чего модель переобучается на всём префиксе с
фиксированным числом итераций. Пятая протестированная компонента (`lgb_strong`,
сильная регуляризация + `scale_pos_weight` 4) отброшена: early stopping срабатывает
мгновенно, PR AUC `0.384` против `0.41`.

## 4. Схема валидации

`src/cv_probs.py` — честная expanding-window схема, устраняющая методологические проблемы
предыдущего поиска:

1. Валидационные блоки **непрерывны по времени** и равны размеру hidden test (7 446 строк),
   так что каждый фолд имитирует «обучись на прошлом, предскажи следующие ~2 месяца».
2. Early stopping **никогда не видит** валидационный блок (внутренний holdout, см. выше).
3. Скрипт CV не выбирает ни порог, ни веса — он только сохраняет вероятности компонент
   (`artifacts/probs_fold*.npz`). Все решающие правила сравниваются офлайн на одних и тех
   же предсказаниях (`src/analyze_rules.py`, `src/rate_curve.py`), поэтому selection leakage
   исключён конструктивно.

Фолды (по `first_event_time`):

| фолд | train, строк | валидация | prevalence валидации |
|---|---|---|---|
| 4 | 18 874 | 2025-08-23 … 2025-10-12 | 0.1270 |
| 3 | 26 320 | 2025-10-12 … 2025-11-27 | 0.1436 |
| 2 | 33 766 | 2025-11-27 … 2026-01-11 | 0.1515 |
| 1 | 41 212 | 2026-01-11 … 2026-03-01 | 0.1468 |

Оговорка, которую честно фиксируем: транздуктивные счётчики (`compute_agg_counts`)
считаются на всём `train + test` один раз, включая «будущие» строки. Метка в них не
участвует, но CV-оценка из-за этого слегка оптимистична; на выбор `m` это не влияет,
поскольку сравниваемые правила используют одни и те же признаки.

## 5. Результаты

Сравнение решающих правил на **champion-бленде** (`0.70/0.20/0.10`), среднее по фолдам
1–3 — только они имеют «прошлое» для forward-правил (`artifacts/analysis_rules.csv`):

| правило | как получено | F1 |
|---|---|---|
| фиксированный порог `0.504` (правило champion) | константа из прошлого решения | 0.4183 |
| порог, подобранный на более ранних фолдах | forward-only | 0.4189 |
| доля единиц с более ранних фолдов | forward-only | 0.4191 |
| доля единиц, отмасштабированная на prevalence фолда | forward-only | 0.4217 |
| **top-k, `k = 1.8 × 990`** | множитель с CV, число позитивов известно | **0.4224** |
| оракульный порог (недостижимая верхняя граница) | подсмотр в метки фолда | 0.4290 |

Тот же top-k-переход на бленде из 4 компонент с усреднением по seed'ам даёт `0.4249`,
то есть суммарно `+0.0066` к правилу champion, при том что оракульная граница выше
champion-правила всего на `+0.0107`.

Онлайн-результаты (public F1): frozen champion `0.4792176039` при `k = 1426`.
Кандидаты этого решения перечислены в `submissions/` — см. раздел 7.

## 6. Воспроизведение

Google Colab: открыть `solution.ipynb`, выполнить ячейки сверху вниз (установка
зависимостей, загрузка `train.csv`/`test.csv` из репозитория, обучение, запись
`submission.csv`). Локально:

```bash
pip install -r requirements.txt
python solution.py            # обучение всех компонент и запись submission.csv
python src/verify_reproducibility.py   # сверка с сохранёнными вероятностями
```

Полное обучение финальных моделей занимает около 4 минут на 2 потоках. Все источники
случайности зафиксированы (`random_seed`/`random_state` = 42, 2026, 777; никаких
операций, зависящих от порядка потоков, кроме детерминированного бустинга).

Исследовательские прогоны:

```bash
python src/cv_probs.py --folds 4 --seeds 42,2026,777   # вероятности по фолдам
python src/cv_probs.py --final --seeds 42,2026,777     # вероятности на test
python src/analyze_rules.py                            # сравнение решающих правил
python src/rate_curve.py                               # F1 как функция доли единиц
python src/make_submissions.py                         # кандидаты в submissions/
```
